# Automated private Coach diagnostics

User needs practical ongoing production debugging because manual SQL exports produced no useful output. Add bounded text-free diagnostics captured during analysis, an owner-only read-only diagnostics API with explicitly labelled reconstruction for legacy records, and an authenticated debug page for JSON download. No forced interventions, paid reanalysis, SRS changes, public/social leakage or production deployment. Preserve current feature branches and main.

## Agreed contract

GET /api/learning/sessions/{sessionId}/coach-diagnostics. Owner session facade + gateway authentication, foreign404/anonymous401. Returns JSON:
{schemaVersion:1, sessionId, analysisId?:string|null, mode:"CapturedAtAnalysis"|"ReconstructedNow", capturedAt, analysis:{status,decision,decisionSource,provider,model,promptVersion,schemaVersion,failureCode,generation,retryCount}, context:{planned,completed,successful,failed,candidateCount,revisionMismatchCards,contentOmittedCards,cards:[{cardId,sessionRevision,currentRevision,selectionReason,currentRevisionEvidenceCount,historicalRevisionEvidenceCount,sessionOutcome?,sessionResponseTimeMs?,status?,masteryScore?,source?,modelVersion?,recentAttempts:[{outcome,reviewedAt,responseTimeMs,learningRevision}]}]}, providerCalled:boolean|null, inputCharacters?:number|null, outputCharacters?:number|null, durationMs?:number|null}.

Text-free snapshot of evidence and selection reasons, never word/translation strings, raw provider output, auth/config/PII or expected exercise answers. Model summary is excluded because free prose may repeat card text. No claim of internal model reasoning. decisionSource differentiates NoCandidates, Provider, Failed, Pending, Disabled, LegacyUnknown. Provider None is permitted and labelled Provider with decision None; don't invent explanation why model chose it. Selection reasons: Included, RevisionMismatch, InsufficientEvidence, NoSessionAttempt, SessionNotProblematic, ContentUnavailable, ContentTooLarge, CandidateLimit; bounded to20 planned cards,6 recent attempts/card. Need reliable distinction not reached after5 vs evaluated? CandidateLimit marks eligible later candidates and avoid expensive unbounded history. Current immutable session counters embedded. Store DiagnosticJson nullable text on CoachAnalysis additive migration; no card content retention. Snapshot captured before provider call persisted with generation fence so Pending/failure request interruption still observable. Retries replace current diagnostic snapshot with last generation; legacy records are honestly reconstructed now. No paid provider call or writes on GET, no learner mutation. No diagnostic fields passed to provider context (strict existing model contract). Ensure cleared tracker doesn't drop snapshot final/failure. Diagnostics must not become normal social or lesson DTO.

Frontend standalone authenticated /coach-diagnostics/:sessionId debug page: calls only GET, explains captured vs reconstructed, renders simple key summary and full JSON using interpolation; Download JSON + retry load. No analysis POST. Add a link from completed session only if route query coachDebug=true to keep implementation details out of normal study flow. RU/EN, mobile, loading/error, auth interceptor reuse, no credentials/sessionStorage handling manually. Link targets route with sessionId.

Verification: full Docker stack/migration, full backend script, frontend tests/build; two-user real gateway diagnostic reads before/after failed/None/intervention + legacy snapshot markers + no learner mutations; browser desktop/mobile read/download. No production deployment; save follow-up commits on feature branches, no push/merge.
